# Архитектура и задачи Tanys

Приложение работает в браузере. React хранит черновик анкеты и результаты в памяти. Статический JSON поставляется со сборкой. Такой подход позволяет показать подбор на ноутбуке без сетевого запроса при нажатии кнопки.

| Модуль | Ответственность |
| --- | --- |
| `src/main.tsx` | Запуск React |
| `src/App.tsx` | Хранит введённую анкету, вызывает подбор, передаёт результат в UI |
| `src/components/` | Форма, список карточек, адаптивный CSS. Типы входных параметров в `props.ts` |
| `src/matching/types.ts` | Общие типы анкеты, кандидата и рекомендации |
| `src/matching/recommend.ts` | Чистая функция подбора, создаётся в #3. Тесты алгоритма рядом |
| `src/data/profiles.json` | База участников, первые записи служат образцом |
| `tests/fixtures/` | Отдельные контрольные запросы и ожидаемые признаки для оценки в #4 |

## Путь данных

Форма вызывает `onSubmit(profile)`. В #5 App получает проверенные анкеты из модуля данных и вызывает `recommend(profile, candidates)`. Функция принимает `ProfileInput` и `readonly Candidate[]`, возвращает `Recommendation[]`. Логика подбора не импортирует React, компоненты не читают JSON. При редактировании App снова передаёт форме предыдущий ввод.

В #4 проверь поля JSON, уникальность ID, допустимые цели и типы до передачи движку. В #3 сначала примени пары целей из брифа. Затем учти, что человек предлагает и что ищет, пересечение навыков, интересы и опыт. При равном балле используй стабильный ID. Построй объяснение из тех же фактов, которые повлияли на порядок.
