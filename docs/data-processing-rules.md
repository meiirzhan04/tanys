# Tanys 1.0 — правила обработки данных и согласия (`#48`)

Документ задаёт перечень данных, сроки хранения/удаления и пользовательские тексты для публичного пилота Tanys 1.0 по контракту [`docs/service-v1.md`](service-v1.md).

> **Ограничение допуска:** до заполнения и утверждения таблицы реквизитов ниже капитаном в сервисе разрешены **только синтетические анкеты** (локально, в демо на Vercel и на staging). Регистрация реальных участников открывается только после утверждения оператора, региона, поставщиков и канала обращений.

## 1. Реквизиты пилота (заполняет и утверждает капитан)

| Параметр | Значение / статус | Примечание |
| --- | --- | --- |
| Оператор данных | `[Утвердить капитану]` | Наименование организатора пилота / юридического или физического лица |
| Ответственный за данные и модерацию | `[Утвердить капитану]` | Имя и роль в команде |
| Канал обращений участников | `[Утвердить капитану]` | Email/форма для запросов доступа, исправления и удаления (SLA ответа ≤ 5 рабочих дней) |
| Регион основной БД (PostgreSQL) | `[Утвердить капитану — для пилота в РК: площадка в РК]` | Учитывает требования Закона РК «О персональных данных и их защите» № 94-V (хранение основной базы граждан РК на территории РК) |
| Регион резервных копий | `[Утвердить капитану — совпадает с регионом БД]` | Шифрование при хранении и передаче (TLS) |
| Поставщик хостинга API и БД | `[Утвердить капитану в связке с #58]` | Один контейнер API + PostgreSQL по внутренней сети |
| Поставщик SMTP (коды входа) | `[Утвердить капитану в связке с #58]` | Используется только для доставки одноразовых кодов (`POST /auth/challenges`) |
| Хостинг статического демо | Vercel (`tanys-new.vercel.app`) | Только вымышленные анкеты, реальные ПДн туда не передаются |
| Версия текстов согласия | `v1` (`consentVersion: "v1"`) | При существенном изменении правил версия увеличивается (`v2`) |

## 2. Перечень обрабатываемых данных (по форме и API)

| Категория | Поля / источник (`service-v1.md`) | Цель обработки | Кто видит |
| --- | --- | --- | --- |
| Учётная запись и вход | Нормализованный `email`, хеш одноразового кода, срок/счётчик попыток, токен сессии (`HttpOnly` cookie) | Вход без пароля и восстановление доступа (`POST /auth/challenges`, `POST /auth/sessions`) | Только сервер и владелец аккаунта; другим участникам не передаётся |
| Анкета участника в событии | `name`, `role`, `skills`, `experienceYears`, `interests`, `about`, `goal`, `lookingFor`, `visible`, `consentVersion` (`PUT /events/E/profile`) | Взаимный подбор топ-5 и объяснение рекомендации внутри одного события | Другие участники события — **только если `visible: true`**; организатор видит состав своего события |
| Контакт для взаимного обмена | `value` (`PUT /me/contact` — Telegram/email/телефон по выбору участника) | Обмен контактом после обоюдного согласия на знакомство | Скрыт до `status: "accepted"` в `PATCH /events/E/introductions/I`; после принятия доступен обеим сторонам пары |
| Взаимодействия в событии | Отметки `met` / `not_a_fit`, блокировки (`PUT /events/E/blocks/U`), запросы знакомства, слоты доступности и встречи 1:1 | Пересчёт выдачи, исключение заблокированных пар, согласование встреч | Только соответствующие участники пары; блокировка скрывает пару в обоих направлениях |
| Модерация и безопасность | Жалоба (`subjectId`, `reason`), решение модератора (исполнитель, действие, время), rate-limit счётчики | Защита участников события от спама и злоупотреблений | Автор видит подтверждение отправки; организатор видит очередь своего события |

**Запрещено собирать и хранить:**
- пароли и открытые (нехешированные) одноразовые коды входа;
- данные, спарсенные из LinkedIn, Telegram или иных внешних источников без явного ввода участником;
- email, имена, тексты `about` и контакты в технических логах, метриках и оповещениях (`#59`).

## 3. Сроки хранения, удаление (`#57`) и резервные копии (`#59`)

| Данные | Срок хранения | Удаление и очистка |
| --- | --- | --- |
| Одноразовые коды входа (`challenges`) | TTL 10–15 минут | Автоматическая очистка просроченных записей ≤ 24 часа |
| Активные сессии | До выхода (`DELETE /auth/session`), восстановления доступа или истечения TTL (≤ 14 дней) | Немедленный отзыв при выходе, восстановлении или удалении аккаунта |
| Анкеты, отметки, знакомства, слоты и встречи события | Период мероприятия + **30 дней** после `status: "closed"` | Плановая автоочистка данных закрытого события (`#57`) |
| Удаление аккаунта по запросу (`DELETE /me`) | До запроса пользователя | Немедленный отзыв сессий и исключение из выдачи; удаление записей из основной БД ≤ 24 часа (по `#57`) |
| Резервные копии PostgreSQL (`#59`) | Ротация **≤ 30 дней** | Записи удалённых аккаунтов вытесняются по ротации; при восстановлении БД из копии повторно применяется минимальный журнал ID удалённых аккаунтов (без ПДн) |
| Журнал жалоб и действий модератора | До **90 дней** после закрытия события | Хранит ID, код причины, действие и время; очищается по истечении срока |
| Технические логи без ПДн | До **30 дней** | Автоматическая ротация |

## 4. Пользовательские тексты для интерфейса (`consentVersion: "v1"`)

Готовые тексты для внедрения в `#50` (вход, вступление, редактирование профиля) и `#52` (взаимный обмен контактами).

### 4.1. Видимость профиля (`visible`)

- **Рус:** «Вашу анкету (имя, роль, навыки, интересы, цель и „О себе“) видят только участники этого мероприятия после того, как вы включите показ профиля. Вы можете скрыть анкету или выйти из мероприятия в любой момент.»
- **Қаз:** «Сауалнамаңызды (атыңыз, рөліңіз, дағдыларыңыз, қызығушылықтарыңыз, мақсатыңыз және „Өзім туралы“) профильді көрсетуді қосқаннан кейін тек осы іс-шараның қатысушылары ғана көреді. Профильді кез келген уақытта жасыруға немесе іс-шарадан шығуға болады.»
- **Eng:** "Your profile (name, role, skills, interests, goal, and 'About') is shown only to participants of this event once you turn profile visibility on. You can hide your profile or leave the event at any time."

### 4.2. Взаимный обмен контактами (`PUT /me/contact` / `introductions`)

- **Рус:** «Ваш контакт для связи и email для входа скрыты от других участников. Контакт откроется собеседнику только после того, как вы оба подтвердите запрос на знакомство.»
- **Қаз:** «Байланыс дерегіңіз бен кіруге арналған email басқа қатысушылардан жасырылады. Байланыс екі тарап та танысу сұрауын растағаннан кейін ғана ашылады.»
- **Eng:** "Your contact details and sign-in email stay hidden from other participants. Your contact is shared with a match only after both of you accept the introduction request."

### 4.3. Согласие при вступлении и право на удаление (`DELETE /me`)

- **Рус:** «Продолжая, я соглашаюсь на обработку данных моей анкеты для подбора собеседников и встреч 1:1 в рамках этого мероприятия (версия правил v1). Анкета и аккаунт удаляются в настройках профиля или по обращению к оператору; данные закрытого мероприятия очищаются через 30 дней.»
- **Қаз:** «Жалғастыра отырып, осы іс-шара аясында сұхбаттасушыларды іріктеу және 1:1 кездесулерді жоспарлау үшін сауалнама деректерімді өңдеуге келісемін (ереже нұсқасы v1). Профиль мен аккаунтты баптауларда немесе операторға жүгініп өшіруге болады; аяқталған іс-шара деректері 30 күннен кейін тазаланады.»
- **Eng:** "By continuing, I agree to the processing of my profile data for matchmaking and 1:1 meeting scheduling within this event (policy v1). You can delete your profile and account in settings or via the operator contact; closed event data is purged after 30 days."

## 5. Требования к реализации в смежных задачах

- **`#49` (хранение анкет):** при создании профиля по умолчанию `visible = false`; публичная выдача подбора возвращает только разрешённые поля анкеты и никогда не включает `email` и `contact`.
- **`#50` (интерфейс входа и профиля):** сохраняет `consentVersion: "v1"` при явном согласии участника и выводит тексты раздела 4.
- **`#52` (знакомство и контакты):** отдаёт контакт только при `status === "accepted"` и отсутствии блокировки.
- **`#57` (удаление и очистка):** реализует `DELETE /me` с немедленным отзывом сессии и скрытием профиля, а также фоновую очистку закрытых событий через 30 дней.
- **`#59` (логи и бэкапы):** маскирует/исключает ПДн из логов и фиксирует ротацию копий ≤ 30 дней.
