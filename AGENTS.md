# Правила работы над Tanys

Сделай минимальный diff в своей области. Сохрани существующие имена полей. Если меняется общий тип, обнови потребителей вместе с ним. Другие функции, документацию и рефакторинг добавляй только по задаче.

## Перед началом задачи

1. Выполни `git fetch origin`. Для нового задания создай отдельную ветку от актуального `origin/main` по правилам ниже.
2. Прочитай свой GitHub Issue, [архитектуру](docs/architecture.md) и [аудит из репозитория](TANYS_AUDIT.md). Для актуальной копии отчёта используй `git show origin/main:TANYS_AUDIT.md`.
3. Сверь выводы аудита с текущим кодом. Для задач про публичное демо отдельно сверь SHA развёрнутой версии и воспроизведи сценарий на публичном URL. Отчёт описывает состояние на момент проверки. Если проблема уже исправлена, приложи доказательство к задаче.

## Ветки и слияние

- Перед каждой GitHub Issue обнови refs через `git fetch origin` и создай отдельную ветку от `origin/main`, например `git switch -c feat/issue-3-matching origin/main`. Если возобновляешь ту же задачу, открой её существующую ветку.
- Коммить изменения только этой задачи в её ветку. Если нужна незамерженная работа из другой задачи, дождись её слияния или явно укажи зависимость в PR.
- Когда задача готова, прогони проверки, отправь ветку в GitHub и открой PR в `main` со ссылкой на Issue. После успешных проверок слей готовую задачу в `main` через PR.

## Обязательные условия кейса

- Анкета содержит роль, стек, опыт, интересы, текст о себе и одну из шести целей из `src/matching/types.ts`.
- В рабочей базе минимум 100 вымышленных анкет, созданных командой. Реальные профили и парсинг LinkedIn или Telegram запрещены.
- Учитывай взаимность целей. Выводи пять разных подходящих людей и объяснение каждому в 1–2 предложениях. Объяснение опирается на поля конкретной пары. При недостатке данных покажи доступные результаты.
- На живой проверке жюри вводит три свои анкеты. Цели — минимум три подходящих человека в каждой пятёрке, выдача быстрее трёх секунд и путь от анкеты до результатов за две минуты.
- Организаторы разрешают правила, эмбеддинги и LLM API. Для этого прототипа команда использует локальный подбор. API-ключи нельзя коммитить или помещать в клиентскую сборку.
- Дополнительные возможности из брифа — три языка, первая фраза, обратная связь с пересчётом, слоты встреч, карта интересов и рекомендации стендов. Реализуй бонус, когда он входит в твою задачу.
- Перед PR запусти профильную проверку и `npm run build`. Укажи PASS или FAIL и строку ошибки. При блокере задай один конкретный вопрос.
